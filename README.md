# radar-failure-hunter

An autonomous agent that hunts for the scenarios where a radar CFAR detector **fails**, explains
**why** each failure class occurs, and writes a reproducible report. It simulates a range-Doppler
map, runs a cross-entropy adversarial search over the scenario space, tags and clusters the
failures it finds, and compares two classic detectors — **CA-CFAR** and **OS-CFAR** — on identical
noise realizations.

Everything is synthetic, seeded, and deterministic: same seeds in, same numbers out.

## How to run

```bash
pip install -r requirements.txt

python hunter.py validate     # clean-scenario Pd vs SNR against Swerling-I theory (~2 min)
python hunter.py hunt         # adversarial failure search + atlas.json + report.md (~4 min)
python hunter.py serve        # interactive web app at http://127.0.0.1:8000 (input -> output)
python -m radar_hunter       # same commands via the installed package entry
python -m pytest             # 18 tests: physics, FA calibration, masking, reproducibility, API (~35 s)
```

### The web app (Scenario Lab)

`python hunter.py serve` starts a FastAPI backend that also hosts the built dashboard:

- **Scenario Lab** — give input, get output: set target SNR, clutter CNR, interferer power and
  displacement, positions, seed, and trials with the sliders (or click a one-click preset:
  Clean, Interferer masking, Clutter edge, Low SNR, Adversarial worst); click **Generate map**
  to render the range-Doppler map (log-power heat colors) with CA-CFAR / OS-CFAR detection
  overlays, target (green) and interferer (orange) crosshairs, plus per-detector hit /
  false-alarm stats for that exact map; click **Run Monte-Carlo** for Pd and FA/map over many
  trials (identical noise realizations for both detectors, so the comparison is fair); click
  **Sweep SNR 4→32 dB** to see how your scenario behaves across SNR, one line per detector.
  The URL always contains your current scenario — copy it to share or bookmark that exact view.
- **Hunt Report** — the full failure-hunt visualization (validation curve vs theory, yield bars,
  scatter of failing scenarios, KMeans clusters with explanations, top-failure table, CSV export
  of all top failures) from `atlas.json` — plus a **Re-run the failure search** card: start a
  quick (~1 min) or full (~4 min) hunt from the browser and watch the progress log live; the
  report refreshes itself when the hunt finishes.

The API is directly usable without the UI:

```bash
curl -X POST http://127.0.0.1:8000/api/simulate -H "Content-Type: application/json" \
  -d '{"snr_db": 15, "cnr_db": 20, "int_db": 25, "dr": 6, "dd": 3, "seed": 42}'
curl -X POST http://127.0.0.1:8000/api/evaluate -H "Content-Type: application/json" \
  -d '{"snr_db": 15, "cnr_db": 20, "int_db": 25, "dr": 6, "dd": 3, "trials": 60, "seed": 42}'
curl -X POST http://127.0.0.1:8000/api/sweep -H "Content-Type: application/json" \
  -d '{"snr_db": 15, "int_db": 25, "dr": 6, "dd": 3, "snr_lo": 8, "snr_hi": 24, "trials": 20}'
curl -X POST http://127.0.0.1:8000/api/hunt/start -H "Content-Type: application/json" -d '{"quick": true}'
curl http://127.0.0.1:8000/api/hunt/status
```

Dashboard development mode (hot reload, proxies /api to the backend):

```bash
cd dashboard
npm install
npm run dev                   # http://localhost:5173 (needs `python hunter.py serve` running)
```

Optional LLM explanations: set `OPENAI_API_KEY` (and optionally `RADAR_HUNTER_LLM_MODEL`) and
cluster explanations in `report.md` are generated by an LLM. **No key is ever required** — the
default is deterministic rule-based text, and any LLM failure silently falls back to it.

## What it does

1. **Simulate** (`radar_hunter/simulator.py`): 128x64 range-Doppler power maps — unit-power complex
   Gaussian noise, Rayleigh-fluctuating target (Swerling I), an optional 3-bin zero-Doppler clutter
   ridge, and an optional strong interferer near the target.
2. **Detect** (`radar_hunter/detectors.py`): one `Detector` interface (`detect(P) -> bool mask`),
   two implementations — CA-CFAR and OS-CFAR (k = 0.75 * N = 312 of 416 training cells, exact
   order-statistic threshold multiplier for the design Pfa).
3. **Search** (`radar_hunter/search.py`): a cross-entropy method concentrates sampling where Pd is
   lowest; a seeded random baseline measures how often failures occur by chance. Both detectors
   see the exact same scenario draws and noise realizations.
4. **Analyze** (`radar_hunter/analysis.py`): rule-based failure tags (interferer masking /
   clutter-ridge leakage / low SNR), failure yield (% of scenarios with Pd < 0.3), and KMeans
   clustering of the failing scenarios' parameters, each cluster labelled with its dominant tag.
5. **Report** (`radar_hunter/report.py`): `atlas.json` (machine-readable, feeds the dashboard) and
   `report.md` (setup, validation curve, per-detector failure yield, top clusters with
   explanations, reproducible seeds).
6. **Dashboard** (`dashboard/`): **Scenario Lab** (interactive input -> live range-Doppler map,
   detection overlays, Monte-Carlo Pd/FA output, SNR sweep, presets, shareable scenario URLs) and
   the hunt report views (validation curve, scatter of failing scenarios colored by Pd,
   top-failure table, detector-comparison bar charts, cluster cards, CSV export, and a button to
   re-run the whole hunt from the browser).
7. **Web server** (`radar_hunter/server.py`): FastAPI app exposing `/api/simulate`,
   `/api/evaluate`, `/api/sweep`, `/api/atlas`, and background-hunt endpoints (`/api/hunt/start`,
   `/api/hunt/status`), hosting the built dashboard — the whole software in one command
   (`python hunter.py serve`).

## Results (deterministic; regenerate with `python hunter.py hunt`)

Clean-scenario validation, 400 Monte-Carlo trials per point, matches Swerling-I theory
(Pd = Pfa^(1/(1+SNR)), before the small CFAR loss):

| SNR dB | 8 | 10 | 14 | 18 | 22 |
|---|---|---|---|---|---|
| theory Pd | 0.28 | 0.43 | 0.70 | 0.87 | 0.94 |
| CA-CFAR Pd | 0.28 | 0.46 | 0.72 | 0.85 | 0.94 |
| OS-CFAR Pd | 0.28 | 0.46 | 0.71 | 0.84 | 0.94 |

False alarms per map in homogeneous noise: ~0.8 for both detectors, as designed
(Pfa * cells = 1e-4 * 8167).

Failure search (cross-entropy, 8 iters x 20 population, seed 1; random baseline n=100, seed 2;
16 trials/scenario; failure = Pd < 0.3):

| detector | worst Pd | failure yield (adaptive) | failure yield (random) | FA/map in clutter |
|---|---|---|---|---|
| CA-CFAR | 0.00 | **42%** | 11% | 85 |
| OS-CFAR | 0.31 | **0%** | 0% | 224 |

What the agent found:

- **CA-CFAR is maskable.** The adversarial search drives its Pd to 0.00 in 3 iterations. Its
  failures cluster at Doppler bin ~7 (within the 10-bin training window of the clutter ridge)
  with CNR ~22-26 dB, plus a pure interferer-masking cluster (interferer ~23 dB inside the
  training ring). Mean Pd of the biggest cluster: 0.00.
- **OS-CFAR keeps detecting, but pays in false alarms.** Its worst Pd is 0.31 and it has *no*
  Pd-failures at all — the 75th-percentile statistic shrugs off a single strong interferer —
  but in clutter scenarios it produces ~224 false alarms/map vs CA's ~85, because its noise
  estimate ignores the ~63 ridge cells in its training window and therefore detects the clutter
  ridge wholesale.
- The adversarial search finds failures ~4x more often than random sampling (42% vs 11%),
  confirming it concentrates on the true failure region.

## Honest limits

- **Synthetic data only.** A single-pulse, perfectly matched-filter signal model with known
  unit-power noise: no range/Doppler straddle, no antenna sidelobes, no Doppler mismatch, no
  waveform-dependent losses, at most one interferer, and a simplified 3-bin Rayleigh clutter
  ridge on a circular map (wrap-around edges).
- **Monte-Carlo estimates.** Pd values in the search use 16 trials/scenario (quantized to 1/16);
  yields and FA counts carry sampling error. The validation curve uses 400 trials/point.
- **FA accounting is deliberately conservative:** false alarms exclude 5x5 boxes around the two
  true objects, and no clutter mitigation (MTI, clutter map) is modeled — clutter-ridge
  detections count as false alarms, which is exactly what exposes OS-CFAR's FA cost.
- **Hit criterion is generous:** any detection within +-1 cell of the target counts as a hit, so
  an interferer placed adjacent to the target can produce a "free" detection.
- **Clustering and tags are heuristics.** KMeans clusters are exploratory summaries over the
  searched scenarios, not a statistical characterization of the full scenario space, and the
  rule-based tags encode prior expectations, not measured mechanisms.
- **This tool produces evidence for engineers, not certification.** It ranks and explains failure
  modes of simplified detectors in a simplified world; it proves nothing about any deployed
  radar.
